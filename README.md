# ALTIORA Canton Fair Map

Mobile-first веб-приложение для обхода подтверждённых точек Canton Fair — по фазам (Phase 1: 64 точки, Phase 2: 64 точки, 23–27 октября 2026).

## Данные

- Источник: `data/Canton_Fair_Phase1_FULL_64_POINTS_MASTER.xlsx`, лист **FULL MASTER LIST** (64 строки, 19 колонок).
- Импорт: `python3 scripts/import_excel.py <xlsx> <фаза>` (нужен Python 3 + `openpyxl`) → `src/data/phase<фаза>.json`.
  Все колонки сохраняются дословно (поле `raw`), плюс разобранный список Booth и Hall.
- Hall и Booth из Excel — authoritative. Координаты стендов не выдумываются: GPS используется только как
  подсказка, текущий Hall выбирается вручную (Hall Selector).

## Фазы

- Каждая фаза — свой Excel (те же 19 колонок, лист **FULL MASTER LIST**) и свой файл `src/data/phaseN.json`.
  Приложение само находит все `phaseN.json`; фаза без файла показывается в переключателе как «нет данных».
- Phase 2: `data/Canton_Fair_Phase2_FINAL_PRIORITY_ROUTE_64_POINTS.xlsx` → `src/data/phase2.json`
  (`python3 scripts/import_excel.py data/Canton_Fair_Phase2_FINAL_PRIORITY_ROUTE_64_POINTS.xlsx 2`).
- Необязательные листы Excel, если есть, тоже читаются:
  - **PRIORITY ROUTE** — стратегический приоритет (A+ = обязательно) и «Правило посещения» по ID MASTER.
    A+ показывается значком «A+», есть режим маршрута «Только A+» и фильтр «A+» в списке; при равных условиях A+ идёт раньше.
  - **ROUTE STRATEGY**, строка «Default-порядок без GPS» — порядок зон, когда нет ни GPS, ни выбранного павильона (Phase 2: B → C → D → A).
    С GPS или выбранным павильоном порядок зон по-прежнему выбирается по минимальной ходьбе от вашей позиции.
  - **FULL LIST SUMMARY**, строка «Phase N» — даты фазы (показываются в переключателе).
- Hall с несколькими павильонами через «;» («10.1; 10.3») разбирается на отдельные павильоны.
- Стенд без номера (только код павильона, напр. International Pavilion «2.1») показывается как «весь павильон».
- Цвета групп: группы Phase 1 — как раньше; подробные группы Phase 2 окрашиваются и сводятся в легенде по семейству
  (первое слово: MARINE, COMMERCIAL, SANITARY, BUILDING, GLASS, WATCHES, PREFAB, INTERNATIONAL); полное название группы остаётся в карточке.
- Переключатель — в шапке («Canton Fair Map · Фаза N ▾»); прямая ссылка: `?phase=2`. Выбор запоминается на устройстве.
- Статусы, маршрут и навигация хранятся отдельно для каждой фазы (у фазы 1 прежние ключи `localStorage` — прогресс не теряется).
  Отметки павильонов «📍 я здесь» общие: здания комплекса те же. Резервная копия JSON помечена фазой.

## Функции

- **Далее** — следующая точка по маршруту. После «Посетила» текущий Hall обновляется, маршрут пересчитывается,
  сразу предлагается следующая ближайшая точка (с «Отменить»).
- **Маршрут** — непрерывная цепочка Hall 1 → 2 → 3…: сначала закрывается текущий Hall, затем ближайший по схеме
  комплекса (nearest-neighbour + 2-opt, штраф за смену корпуса и переход через дорогу). Внутри Hall — по порядку стендов.
  Режимы: «Ближайшие», «Сначала A», «Только A». Сверху: текущий Hall, текущая и следующая точка, следующий Hall, счётчики.
- **Карта** — схема Canton Fair Complex (Area A/B/C/D, Hall, этажи), кластеры точек по Hall с цветами групп,
  нумерация и линия маршрута, текущий/следующий Hall, легенда. Нажатие на Hall — список точек в нём.
- Цвета товарных групп (поле «Группа для будущей карты») едины для карты, списка, карточки, маршрута и статистики (`src/groups.ts`).
- Статусы: Посетила, Получить цену, Follow-up, Пропустить, Контакт получен + заметки. Хранятся в `localStorage`.
- **Список**, **Статистика**, экспорт CSV/JSON — без изменений.

## Схема комплекса

`src/venue.ts` — план комплекса по официальному Exhibition Section Floor Map 140-й сессии (Phase 1) и Complex Layout:
позиции корпусов (ground floor x.1, без изометрического скоса), открытые площадки x.0, Pearl Promenade, Middle Platform,
переход над Xingang Donglu в Area C, связь D ↔ A. Маршрут считается по ортогональному графу проходов (Dijkstra);
этажи x.1–x.4 — один корпус (вертикальный переход). Координат стендов нет — точки привязаны только к Hall.

## GPS-навигация

- `src/useGps.ts` — `navigator.geolocation.watchPosition`; разрешение запрашивается при первом открытии «Карты».
- `src/geo.ts` — привязка плана комплекса к GPS (подобие: масштаб, поворот, сдвиг): по реальным координатам Hall
  из AMap POI / hallGeo.json, а пока их нет — по двум станциям Line 8 (Xingangdong, Pazhou), точность ≈ ±100 м. На месте уточняется кнопкой
  «Я в Hall X: уточнить привязку» (калибровочные точки сохраняются локально).
- Маршрут строится от GPS-позиции: порядок Area (перебор), внутри Area — тур по корпусам (nearest-neighbour + 2-opt),
  этажи одного корпуса подряд, внутри Hall — по номерам стендов (логический порядок, не GPS).
- Порядок фиксируется (`lock`) и пересчитывается только при событиях: первая GPS-позиция, ручной выбор Hall,
  «Пропустить», посещение вне очереди, смена режима, «Перестроить». При сильном отклонении — подсказка
  «Есть более короткий маршрут».
- Вне комплекса — ссылки на пешеходный маршрут в Apple Maps / Amap.

## Карта AMap (高德) JS API 2.0

Вкладка «Карта» → «Карта AMap»: реальная карта Гуанчжоу, синяя GPS-точка с точностью, режим следования,
нумерованные маркеры (цвет = товарная группа), порядок обхода и пешеходный маршрут **AMap.Walking**
от GPS до следующей цели. GPS (WGS-84) переводится в GCJ-02 (`src/coords.ts`). Координаты Hall — только из
AMap PlaceSearch (`src/poi.ts`: 中国进出口商品交易会展馆 / 广交会展馆 / Canton Fair Complex / A–D区 / N号馆);
Hall без POI не получает выдуманной точки. Найденное можно выгрузить кнопкой «Скачать hallGeo.json» и
закоммитить в `src/data/hallGeo.json`. «Схема залов» — запасной вид.

Настройка — AMap Overseas Platform (ключи не хранятся в коде):

- Скрипт: `https://sg-webapi.opnavi.com/maps?v=2.0&key=VITE_AMAP_KEY` (не `webapi.amap.com`).
  До загрузки: `window._AMapSecurityConfig = { securityJsCode: VITE_AMAP_SECURITY_KEY }`,
  `window._AMapServiceConfig = { type: 'oversea_sg' }`; карта `{ viewMode: '2D', zoom: 16, showOversea: true }` (`src/amap.ts`).
- Vercel → Environment Variables (Production): `VITE_AMAP_KEY`, `VITE_AMAP_SECURITY_KEY`, затем **Redeploy** — переменные
  `VITE_` встраиваются при сборке. `AMAP_SECURITY_CODE` больше не используется.
- Если в настройках ключа включён whitelist доменов/referrer — добавьте `altiora-canton-fair-map.vercel.app`
  (для preview-сборок — также их `*.vercel.app` домены).
- При ошибке карта показывает errcode / errmsg / errdetail, endpoint, наличие `window.AMap` и сообщения AMap из консоли.

## Запуск

```bash
npm install
npm run dev      # разработка
npm run build    # production-сборка в dist/
```

## Vercel

Импортируйте репозиторий в Vercel — framework **Vite** определяется автоматически (`vercel.json`):
build `npm run build`, output `dist`. Backend и переменные окружения не нужны.
